# kube-foundry v1.0.0

The first complete release of the local Kubernetes reference platform.

## Included

- A pinned three-node kind/Cilium platform with Envoy Gateway and local TLS
- FastAPI, worker, PostgreSQL, Redis, and web workloads with enforced isolation and admission controls
- Prometheus/Grafana observability, API autoscaling, and disruption budgets
- Argo CD reconciliation and scanned GitHub Actions/GHCR digest delivery
- A release-revision-pinned installer using published images
- Safe credential initialization, logical database backup/restore tools, and isolated recovery drills
- Setup, upgrade, rollback, teardown, screenshots, and explicit support boundaries

## Acceptance

The [acceptance record](https://github.com/chriswayneh/kube-foundry/blob/v1.0.0/docs/release.md#acceptance-record) covers a clean three-node install, policy and HTTPS checks, actual image-pull failure and recovery, and byte-equivalent item/job contents after logical database restoration. Existing development data is preserved; failure drills run on a separate cluster with new credentials. Actual Argo CD and Grafana screenshots are included.

## Known limitations

Local kind only. No application authentication, production high availability, scheduled/off-cluster backups, Redis queue restore, alert paging, SSO, or automatic staging/production promotion. TLS is self-signed and Metrics Server has a local kubelet TLS exception. Controller installation remains Helm-managed. No automatic pruning or destructive database replacement is enabled.

## Getting started

Follow the [tagged README](https://github.com/chriswayneh/kube-foundry/blob/v1.0.0/README.md). Use `make install GITOPS_REVISION=v1.0.0` to keep the root and child Applications on this release. Following main is an explicit development choice.
